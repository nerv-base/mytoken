# MyToken!!!!! 路线图

> 状态：2026-10-19 随 0.5.0 重写。0.5 的定位与数据层设计见 [ARCHITECTURE.md](ARCHITECTURE.md)；本文记录定位、做/不做的边界和之后的方向。
> 0.4.x 及以前的“中转站对账 + 缓存账本”路线已放弃，相关代码在 0.5 删除。

## 定位

本机 AI 编程工具的**花费与套餐额度看板**。

- 主窗口回答：今天、这个月花了多少（API 等价），各套餐额度还剩多少。
- 菜单栏 / 托盘回答：现在正在烧多少——今日花费、额度条、正在进行的会话的输出速度、命中率和每小时花费。
- 年度热力图、连续使用天数、排行等回顾内容放在次要位置（排行页）。

与 ccusage、codeburn、tokscale、CodexBar 等工具相比，MyToken 的取舍是：一个原生桌面应用 + 菜单栏，零配置覆盖尽量多的工具，花费和额度放在同一处。

## 不做

- 中转站对账、供应商倍率、折扣——花费只按官方 API 价格计。
- 预算与提醒。
- 多实例；每个工具只有“自动检测的目录”或“用户手动指定的目录”。
- 缓存账本；缓存只保留一个命中率指标。

## 口径

- **花费 = 官方 API 价格**，界面统一标注“API 等价”。没有价格的模型显示“未定价”，不按 $0 计入；用户可以在设置里给它指定按哪个模型计价，或填自定义单价。
- **token 主数字不含缓存读取**；明细拆成输入 / 输出 / 缓存读取 / 缓存写入。
- **缓存命中率**只有一个公式：`cache_read / (input + cache_read + cache_write)`。
- 缓存写入分 5 分钟（1.25× 输入价）和 1 小时（2× 输入价）两档。
- 历史只增不删：工具清理旧日志后，已入库的用量保留；全量重扫不清空历史。

## 隐私

- 默认网络请求：价格表（models.dev → LiteLLM），以及每天一次到 github.com 检查更新（不能自我更新的构建不检查；命令行从不检查）。
- 套餐额度一律从服务商服务器读取（见 [ARCHITECTURE.md](ARCHITECTURE.md#plan-quotas)）；只在检测到本机已存的凭据时，用该凭据访问该服务本身，绝不刷新或改写凭据。

## 性能硬指标

在维护者真实数据副本上实测（约 25.5 万事件），见 [ARCHITECTURE.md](ARCHITECTURE.md#performance-budgets)：全新全量扫描 ≤ 15 秒、增量扫描 ≤ 25 ms、空闲后台 CPU < 0.5%、文件句柄 < 150、界面刷新 < 25 ms、单帧 ≤ 8 ms、CLI 只读命令 < 150 ms。

## 0.5.0（当前）

- 删除中转站 / 对账 / 倍率 / 多实例 / 预算 / 缓存账本，数据库原地迁移（保留历史、重新计价、VACUUM）。
- 修复 Claude Desktop 与 Claude Code 的重复计数、Cowork 按轮去重、1 小时缓存写入计价、ledger 去重键精度。
- 扫描重写为线性：全新扫描从 23 分钟降到约 13 秒；监听目录有上限，空闲时几乎不占 CPU。
- 统一的套餐额度服务：Codex、Claude、Cursor、Copilot、GLM、DeepSeek、Trae、WorkBuddy、Qoder、ZCode，全部从服务商服务器读取。
- 界面基于 MyGo v0.5.5 重写：概览 / 会话 / 排行 / 项目 / 设置五页；托盘弹出面板；Windows 托盘支持右键菜单退出。
- CLI 精简为：摘要、按天表格、额度、扫描、statusline、doctor、version，读命令全部只读打开。

## 之后

- 继续扩充工具覆盖，优先补齐真实日志验证；没有 1 小时缓存信号的工具（zed、kimi、codebuff、workbuddy、mux、amp）跟进上游格式。
- 更多套餐额度来源（Gemini CLI、Kimi Code、MiniMax、Factory Droid 等，取决于是否有可用的本地凭据和接口）。
- 去掉数据库里残留的 `instance_id` 列（0.5 为降低迁移风险暂时保留）。
