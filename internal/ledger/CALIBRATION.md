# task-20 缓存账本：只读真实数据校准报告

## 范围与复现

只读授权副本 `/tmp/rd/c1/mytoken.db`，使用 `mode=ro` 和 `query_only(1)` 双重限制；未访问用户 live 数据目录。只查询事件的时间、token、模型、harness、resolved_provider、边界及内部用于分组的会话标识；报告不输出原始会话 ID、项目、提示或凭据。

```sh
MYTOKEN_LEDGER_CALIBRATE=1 go test ./internal/ledger -run TestReadOnlyCalibration -v -count=1
go test ./internal/ledger -run '^$' -bench BenchmarkAnalyze200K -benchtime=5x -count=1
```

样本为 216,036 请求、2,189 会话；401 请求属于全链无正缓存字段的 `uncacheable` 链，215,635 请求进入账本。副本是历史解析结果，未因其他成员本轮 parser 更新而重扫。

## 最终规则与防误报决策

完整契约见 [CACHE §2/§3](<docs/CACHE.md#2-应命中的推断internalledger纯函数无-io>)。

- 已观察到的历史 **P 和 CacheRead 都是分支证据**。pi 的 4480、DSH 的 11392 等固定短读不应被历史最大 P 压成巨额 miss。
- Anthropic 只将 **R+W 断点**当可缓存前缀，不把未缓存的尾部 Input 算成下次应命中。真实 `P=72974,W=60789 → R=60789` 的 12185 误报已消除。
- 前缀证据按 harness/provider/model 隔离，换中转站不复用旧站证据；模型家族优先于中转站显示名称。
- Boundary 表示**本请求之前**，不再检查上一条 Boundary，因此 compact 只记一次。无显式边界时要求骤降至 <60%，再由连续两条同站同模型请求复用新前缀确认；已知短分支优先排除。
- 无法比较的缩短请求按冷分支处理；日志全链没有缓存可观测性时排除，而不是把可缓存链中偶发 R=0 排除。
- 索引保留全部历史，不用固定窗口遗忘旧分支；按长度离散化的最大序号树及 TTL/epoch 下界实现 O(n log n)，坐标中出现未来长度不等于用了未来缓存证据。
- `unexplained` 只是现有字段不能解释，**不能直接认定中转站有错**；客户端改写、未知并行分支、上游驱逐等仍无法排除。
